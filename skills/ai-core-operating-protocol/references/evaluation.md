# Domain-Specific Evaluation

Build acceptance criteria from real failure modes, not a generic “looks good” score.

- **Code:** targeted tests, build/type/lint where applicable, runtime behavior, regression risk, security.
- **Research:** authoritative/current sources, contradiction checks, unsupported claims, scope completeness.
- **Documents:** names, dates, numbers, source fidelity, requested structure, usable output.
- **Data:** traceable inputs, formulas, units, date ranges, reconciled totals, visible missingness.
- **Tool actions:** correct target, correct action, intended resulting state, no unintended side effect.
- **Creative work:** audience, purpose, constraints, factuality, originality, requested format, prior feedback.

Repair loop: identify failed criterion → change the minimum necessary part → rerun that check → stop when material criteria pass or a real blocker remains.
